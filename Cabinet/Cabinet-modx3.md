# Cabinet для MODX 3

Версия Cabinet для MODX Revolution 3: REST API кабинета (`assets/components/cabinet/api.php`), классы в `core/components/cabinet/src`,
интеграция с MiniShop3. Общее устройство, сниппеты, чанки и события такие же, как в версии для MODX 2 — см. [Cabinet.md](Cabinet.md).
Здесь — то, что в версии для MODX 3 устроено иначе или есть только в ней.

## ✨ Отличия от версии для MODX 2

- Вход по коду из SMS/звонка без пароля (`cabinet_auth_login_otp`)
- Капча по порогу для входа по коду: Yandex SmartCaptcha или Google reCAPTCHA v3 на выбор
- Лимиты попыток на всех путях: вход, восстановление, регистрация, проверки доступности, ввод кода, смена пароля;
  счётчики атомарны — пачка параллельных запросов лимит не обходит
- Имена системных настроек лимитов отличаются (таблица ниже)
- Провайдер телефона указывается коротким именем (`AlphaSms`) или полным именем класса
- Интеграция с MiniShop3 вместо miniShop2

## 📱 SMS/Voice OTP

### Провайдер

Укажите провайдера в настройке `cabinet_phone_handler_class` — коротким именем встроенного провайдера или полным
именем своего класса, реализующего `Cabinet\Phone\PhoneInterface`. По умолчанию `PhoneLog` — тестовый провайдер,
который ничего не отправляет, а пишет SMS и коды звонков в журнал ошибок MODX.

| Провайдер                               | Страна | SMS | Звонок | Настройка конфигурации     | Ключи JSON-конфигурации                |
|-----------------------------------------|--------|-----|--------|----------------------------|----------------------------------------|
| [GreenSms](https://greensms.ru/)        | RU     | ✓   | ✓      | cabinet_greensms_config    | `login`, `password`, `api_key`, `sender`, `lang` |
| [TeraSms](https://terasms.ru/)          | RU     | ✓   | ✓      | cabinet_terasms_config     | `login`, `password`, `token`, `sender` |
| [AlphaSms](https://alphasms.ua/)        | UA     | ✓   | ✓      | cabinet_alphasms_config    | `api_key`, `sender`                    |
| [SmsClubMobi](https://smsclub.mobi/)    | UA     | ✓   | ✗      | cabinet_smsclubmobi_config | `api_key`, `sender`                    |
| PhoneLog                                | Demo   | ✓   | ✓      | —                          | —                                      |

Пример: `cabinet_phone_handler_class` = `AlphaSms`, `cabinet_alphasms_config` = `{"api_key": "…", "sender": "MyShop"}`.

Если класс провайдера не найден или не создаётся, Cabinet пишет ошибку в журнал и переключается на `PhoneLog`:
SMS при этом не уходят. После смены провайдера проверьте журнал ошибок.

### Режим и код

| Настройка                      | По умолчанию | Описание                                                                                  |
|--------------------------------|--------------|-------------------------------------------------------------------------------------------|
| cabinet_otp_phone_mode         | sms          | `sms` — код в SMS, `call` — код звонком (его задаёт провайдер, обычно 4 цифры)            |
| cabinet_otp_phone_code_length  | 4            | Длина кода в SMS. В режиме `call` принимается код провайдера любой длины                  |
| cabinet_otp_ttl                | 180          | Время жизни кода, сек. Таймер повторной отправки на форме — то же значение               |
| cabinet_link_ttl               | 600          | Время жизни ссылки активации в режиме e-mail, сек.                                        |

Номера `8XXXXXXXXXX` (11 цифр без «+») приводятся к международному виду: RU/KZ → `+7…`, украинский формат `8 0XX…` →
`+380…`. Местный формат `0XXXXXXXXX` не меняется: он совпадает с местными форматами других стран.

## 🔑 Вход по коду из SMS/звонка

Настройка `cabinet_auth_login_otp` (по умолчанию `Нет`) работает только при `cabinet_auth_mode = phone`.

- Форма входа запрашивает только телефон (поле с маской, кнопка «Получить код»); поле пароля и ссылка «Забыли пароль» скрыты.
- Код приходит SMS или звонком (по `cabinet_otp_phone_mode`) и вводится в форму подтверждения с таймером и повторной отправкой.
- **Пароль пользователя не меняется** — это отдельный путь, не восстановление пароля.
- Неактивный пользователь после верного кода активируется и входит. Заблокированному — отказ и при запросе кода, и при вводе.
- Пользователь ищется только по полю телефона профиля. Если номер записан у нескольких профилей, код не отправляется.
- Выключение настройки гасит уже выданные коды: подтверждение и повторная отправка отказывают.
- Пока код жив, новый не выдаётся; повторная отправка — после окончания таймера.
- Код хранится хешем, отдельно для каждой сессии: чужая сессия, запросив код на тот же номер, не затирает и не сжигает код владельца.
- Плагин на `OnBeforeWebLogin` может запретить вход так же, как при входе по паролю.

## 🛡️ Безопасность

### Лимиты

Попытка засчитывается атомарно (под блокировкой MySQL `GET_LOCK`) до проверки пароля или кода, поэтому параллельные
запросы лимит не обходят. Успешный вход и успешная смена пароля сбрасывают свой счётчик.

| Что ограничивается                      | Число попыток                                | Период                                         | Счётчик            |
|-----------------------------------------|----------------------------------------------|------------------------------------------------|--------------------|
| Вход                                    | cabinet_login_attempts_limit (10)            | cabinet_login_lock_time (15 мин)               | логин + IP         |
| Восстановление пароля                   | cabinet_recovery_attempts_limit (5)          | cabinet_recovery_lock_time (15 мин)            | логин + IP         |
| Код активации при входе неактивного     | cabinet_recovery_attempts_limit (5)          | cabinet_recovery_lock_time (15 мин)            | пользователь + IP  |
| Регистрация                             | cabinet_signup_attempts_limit (10)           | cabinet_signup_lock_time (60 мин)              | IP                 |
| Проверка доступности полей              | cabinet_availability_attempts_limit (60)     | cabinet_availability_lock_time (1 мин)         | IP                 |
| Ввод кода                               | cabinet_otp_verify_attempts_limit (5)        | cabinet_otp_verify_lock_time (15 мин)          | код / номер + сессия |
| Отправка кода                           | cabinet_otp_phone_sending_limit (3)          | cabinet_otp_phone_sending_lock_time (360 мин)  | номер + IP; всего на номер — лимит × 2 |
| Неверный текущий пароль при смене       | cabinet_password_change_attempts_limit (5)   | cabinet_password_change_lock_time (15 мин)     | пользователь       |

Значение 0 отключает лимит. IP клиента берётся из `REMOTE_ADDR`; заголовку `X-Forwarded-For` Cabinet доверяет только
для адресов из `cabinet_trusted_proxies` (точные IP через запятую, подсети не поддерживаются).

### Рекомендации для входа по коду

- Код из 4 цифр в одиночку открывает аккаунт, от перебора его защищают лимиты. С настройками по умолчанию на номер
  выдаётся не больше 6 кодов за 6 часов по 5 попыток — не больше 30 попыток из 10 000, около **0,3%** шанса угадать
  код за окно. Каждое увеличение лимитов пропорционально увеличивает этот шанс.
- **Не ставьте `cabinet_otp_phone_sending_limit = 0`**: это отключает лимит отправок, и перебор ограничен только
  5 попытками на каждый новый код, а новые коды можно запрашивать без ограничений (и без ограничения стоимости SMS).
- **Для боевого сайта включите капчу по порогу**: `cabinet_auth_login_otp_captcha_after` = 2–3 и провайдер
  `cabinet_auth_login_otp_captcha` с заданными ключами (см. ниже). По умолчанию порог выключен (0).
- Длина кода 6 цифр снижает шанс угадать в 100 раз, но в режиме `call` код задаёт провайдер звонка — обычно 4 цифры.

### Капча по порогу для входа по коду

| Настройка                              | По умолчанию | Описание |
|----------------------------------------|--------------|----------|
| cabinet_auth_login_otp_captcha_after   | 0            | После стольких отправок кода входа на номер (со всех IP за окно `cabinet_otp_phone_sending_lock_time`) каждый следующий запрос кода требует капчу. 0 — выключено. Лимиты действуют всегда |
| cabinet_auth_login_otp_captcha         | —            | `smartcaptcha` (Yandex SmartCaptcha) или `recaptcha` (Google reCAPTCHA v3). Пусто — провайдер, для которого заданы ключи; включённый на сайте — в приоритете |

Нужны ключи выбранного провайдера (`cabinet_ya_smartcaptcha_client_key` / `_server_key` или
`cabinet_recaptcha_public_key` / `_secret_key`); включать капчу для всех форм не обязательно. Пока порог не достигнут,
пользователь капчу не видит: при достижении сервер отвечает `captcha_required`, и форма показывает SmartCaptcha или
сама повторяет запрос с токеном reCAPTCHA. Если порог задан, а провайдер не настроен, раз в сутки в журнал ошибок
пишется предупреждение, а защищают только лимиты.

### Капча для форм

- **reCAPTCHA v3** (`cabinet_enable_recaptcha`) проверяется на каждом запросе форм; токен формы получают сами.
- **Yandex SmartCaptcha** (`cabinet_enable_ya_smartcaptcha`) проверяется для действий из
  `cabinet_ya_smartcaptcha_verify_actions` (по умолчанию `auth/login,auth/signup,auth/confirm,auth/recovery,auth/confirm/otp/phone/resend`).
  Действие сравнивается по каноничному имени маршрута, поэтому варианты написания (`Auth/Login`, `auth//login`)
  проверку не обходят, а некорректное имя действия отклоняется. Таймаут запроса проверки — `cabinet_ya_smartcaptcha_timeout` (3 сек).

### Прочее

- CSRF-защита (`cabinet_enable_csrf`) включена по умолчанию.
- Ссылка выхода из `cabinetLogin` содержит CSRF-токен: **вызывайте сниппет некэшированным** — `[[!cabinetLogin]]`,
  иначе ссылка выхода перестанет работать.
- Подтверждение смены почты по ссылке срабатывает только для пользователя, который её запросил; при подтверждении
  смены телефона повторно проверяется, что номер не занят другим аккаунтом.

## 💻 Разработка

- Проверка кода: `cd core/components/cabinet && composer qa` (php-cs-fixer, rector, unit-тесты); автоисправление стиля — `composer qaf`.
- Интеграционные тесты на настоящем ядре MODX 3 и базе (`modxkit/testbench`):
  ```bash
  cd core/components/cabinet
  docker compose -f vendor/modxkit/testbench/ci/docker-compose.yml up -d --wait mysql
  MODX_TESTBENCH_DB_HOST=127.0.0.1 MODX_TESTBENCH_DB_USER=root MODX_TESTBENCH_DB_PASS=testbench composer test:integration
  ```
- Сборка фронта: `cd assets/components/cabinet/dev && npm run build`.
